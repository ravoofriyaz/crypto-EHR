Abstract
The rapid digitalization of the healthcare sector has brought significant benefits but has also introduced critical vulnerabilities regarding data privacy and security. The "Cryptography-EHR" project introduces a highly secure Electronic Health Record (EHR) management system designed to mitigate risks of data breaches and unauthorized access. At its core, the system leverages a multi-layered cryptographic architecture to protect sensitive patient information. Medical records and diagnostic documents are encrypted using the AES-256-GCM algorithm, which provides both confidentiality and authenticity. For enhanced key management, the symmetric AES keys are protected via RSA asymmetric encryption, ensuring that only authorized entities can decrypt the data.

To guarantee the integrity and non-repudiation of medical records, the system implements digital signatures using the doctor's RSA keys. Every record is hashed using the SHA-256 algorithm and signed, creating a verifiable forensic trail. Identity management is handled through SHA-256 hashing of user identifiers, allowing for secure lookups without exposing plain-text sensitive data. The platform also features a sophisticated role-based access control (RBAC) mechanism, accommodating patients, doctors, pharmacists, and hospital administrators.

User experience is prioritized through an intelligent symptom-to-specialization mapping engine. This feature allows patients to input their medical complaints and receive automated recommendations for appropriate hospital departments and specialists, covering 30 distinct medical fields ranging from Cardiology to Pediatrics. Secure access is further reinforced by a two-factor authentication (2FA) system utilizing Twilio-based OTP verification. Additionally, the system includes a robust audit logging module recording all data interactions for full accountability. For critical scenarios, an emergency override protocol is implemented, allowing medical professionals access during life-threatening situations while maintaining a strict audit trail. This integrated approach combines advanced cryptography with a user-centric healthcare workflow, providing a scalable and secure solution.

Keywords

SYSTEM ANALYSIS

3.1 Existing System

In traditional healthcare systems globally, patient medical records are typically stored in legacy centralized electronic databases or, in many rural and developing scenarios, still maintained exclusively as physical paper-based records. These conventional file-based systems theoretically allow healthcare providers to record and aggregate patient details such as baseline personal information, longitudinal medical history, long-term prescriptions, laboratory diagnostic reports, and ongoing treatment plans. While such digital and physical systems undeniably make it easier to manage, index, and historically access patient data compared to purely manual archival methods, they exhibit several profound and increasingly dangerous systemic drawbacks in the modern era of cyber threats.

Fundamentally, most existing Electronic Health Record (EHR) systems severely lack robust, active security measures. The database architectures are almost inherently centralized without any form of field-level encryption, meaning all sensitive patient data is stored in plaintext within a single localized server location. This fundamentally creates a massive single point of failure. Consequently, these outdated frameworks present an incredibly attractive, high-value target for sophisticated cyberattacks, ransomware deployment, and automated data scraping scripts. Furthermore, traditional systems typically rely on weak, password-only access control mechanisms (such as basic Discretionary Access Control), making it incredibly difficult to dynamically restrict granular data access based on specifically assigned user roles. As an inevitable result, unauthorized users—including unprivileged hospital staff or administrative personnel—may easily gain untracked access to strictly confidential patient information.

Another critical limitation deeply embedded in existing systems is the severe lack of active privacy protection and data sovereignty. Patients typically have absolutely no technical control over who can seamlessly access their private medical records, nor are they notified when their records are viewed, which exponentially increases the risk of undetected personal data misuse. The pervasive use of weak database encryption protocols—or frequently, the complete absence of any payload encryption—further exposes the entire hospital ecosystem to devastating, irreversible data breaches, severe medical identity fraud, and compliance violations regarding global healthcare data laws like HIPAA.

In summary, while traditional EHR paradigms incrementally improve basic data management functionality compared to manual record-keeping, they fall dangerously short in terms of dynamic security, absolute patient privacy, and verifiable access control. These compounding vulnerabilities aggressively highlight the immediate, non-negotiable need for significantly more secure, mathematically verifiable solutions. Implementing rigorous cryptography-based and privacy-preserving EHR architectures is the only viable method to permanently protect sensitive healthcare information against evolving, highly structured modern cyber threats.

Disadvantages of Existing Systems:
1. Weak Security Mechanisms: Legacy systems often deploy basic perimeter security, leaving actual diagnostic data entirely unencrypted and highly susceptible to direct database extraction.
2. High Risk of Data Breaches: The lack of advanced encryption frameworks ensures that if the main server is compromised, thousands of patient records are instantly exposed in plaintext.
3. Unauthorized Access: Because traditional systems use basic password verification without hardware tokens or biometrics, malicious internal or external actors can easily breach user accounts.
4. Lack of Role-Based Access: Systems lack strict hierarchical privileges, frequently allowing standard clerical staff to view highly sensitive diagnostic files without clinical justification.
5. Single Point of Failure: Operating entirely on centralized, unencrypted server storage means a single network failure or targeted cyberattack can paralyze an entire healthcare facility.
6. Limited Data Integrity: Without cryptographic hashing, there is no mathematical verification to prove that a medical record has not been maliciously altered or tampered with by an insider.
7. No Proper Audit Trails: Old architectures lack autonomous logging, meaning administrators cannot track exactly who viewed a file, what time they viewed it, or from what IP address.
8. Interoperability Issues: Traditional systems use closed architectures that make it extremely difficult to securely share diagnostic data across different hospital networks without compromising privacy.
9. Data Loss Risks: Because data is rarely distributed securely using redundant encrypted clusters, hardware failures frequently result in the permanent loss of vital historical patient data.
10. Lack of Patient Control: Patients remain completely blind to their own data; they cannot track who accesses their medical journey, violating principles of modern digital data ownership.
11. Scalability Problems: Hardware-bound legacy systems struggle to accommodate the massive data throughput generated by modern hospitals without experiencing severe performance bottlenecks.
12. Insider Threats: Without compartmentalized data encryption, disgruntled employees or compromised administrative accounts have unrestricted lateral movement to steal private medical dossiers.
13. Poor Transparency: Clinical and diagnostic workflows occur in a black box, making it exceptionally difficult for regulators to verify if health data protocols are being legally followed.
14. Compliance Challenges: Failing to actively mask personal identifying information (PII) regularly triggers massive penalties concerning global health guidelines like HIPAA and GDPR.
15. High Maintenance Costs: Continuously patching vulnerable, monolithic legacy software databases requires immense IT capital, far exceeding the operational costs of modern cloud-secured architectures.


3.2 Proposed System

The proposed system, formally termed "Cryptography-EHR," is a highly secure, technologically advanced Electronic Health Record (EHR) management platform fundamentally designed to comprehensively protect sensitive healthcare data through the active deployment of military-grade cryptographic techniques and heavily structured access control mechanisms. The system systematically addresses and elegantly resolves the major, pervasive security challenges faced throughout modern digital healthcare environments—specifically mitigating devastating data breaches, unauthorized server access, internal credential stuffing, and silent diagnostic data tampering.

The operational core of the proposed system relies entirely on a multi-layered cryptographic framework strictly designed to mathematically ensure the confidentiality, absolute integrity, and unforgeable authenticity of all patient medical records. To achieve this, every single medical record, uploaded diagnostic document, and pharmaceutical prescription is immediately encrypted using the Advanced Encryption Standard with Galois/Counter Mode (AES-256-GCM). This specific algorithm not only provides incredibly strong baseline data protection but also inherently validates ciphertext authenticity, shielding the database from injection attacks. To go a step further and comprehensively secure the symmetric encryption keys, these AES keys are dynamically encrypted using high-grade RSA asymmetric encryption (2048-bit). This complex architecture securely ensures that absolutely only authorized users holding the mathematically appropriate private keys can decipher the target information, effectively blinding the data even from the central database administrators.

In order to actively maintain flawless data integrity and enforce strict clinical non-repudiation, the system robustly implements specialized digital signatures dynamically generated via the doctor's secure RSA private key. During the generation of any clinical file, the medical record is compressed and hashed using the secure SHA-256 hashing algorithm just before being digitally signed. This vital process mathematically ensures that any microscopic fractional modification made to the record will inherently break the hash signature and instantly be detected, thereby permanently maintaining a transparent, tamper-proof audit trail that guarantees the absolute purity of the medical data. 

To govern interactions with this secured data, the system actively incorporates a strict Role-Based Access Control (RBAC) model managed via verifiable JSON Web Tokens (JWT). This model assigns highly specific, rigid access privileges to vastly different user archetypes: patients, active doctors, dispensing pharmacists, and supervising hospital administrators. This explicit authorization routing ensures that users dynamically access absolutely only the limited fragments of information that are completely necessary for their professional responsibilities, aggressively reducing the potential footprint for accidental or malicious data exposure. Furthermore, to exponentially enhance front-door security during initial login and elevated system workflows, the platform deeply integrates immediate Two-Factor Authentication (2FA) through Time-Based One-Time Password (OTP) verification utilizing scalable Twilio network services. This non-negotiable additional authentication layer strictly prevents unauthorized actors from successfully breaching sensitive healthcare networks, even if root login credentials or passwords are somehow perfectly compromised.

Another highly intelligent, patient-centric feature of the proposed comprehensive system is the integration of an advanced symptom-to-specialization recommendation heuristic engine. Sick patients can easily input their unstructured qualitative symptoms into the interface, and the backend Node.js system intelligently translates and dynamically maps these text strings to the most clinically relevant medical departments and verified specialists spanning across approximately 30 highly distinct hospital specialties (including complex fields like cardiology, dermatology, severe neurology, and pediatrics). This mapping feature profoundly improves patient convenience and definitively assists in greatly accelerating the initial medical consultation workflow.

Finally, the system is actively monitored by an autonomous, comprehensive audit logging mechanism. This background engine silently records every single metadata action performed anywhere within the hospital platform, dynamically documenting record creation, individual access queries, modification attempts, and critical emergency security overrides. This guarantees full forensic transparency and legal accountability across all system interactions. Particularly in life-threatening emergency situations where standard authorizations are too slow, the system provides a specialized "Emergency Access Override" feature. This directly allows authorized healthcare professionals to securely access a dying patient's critical medical history without waiting for SMS OTP checks; however, all such vital accesses are immediately broadcasted to administrators via SMTP and Twilio alerts and strictly logged to permanently prevent clinical misuse.

Overall, the proposed system seamlessly integrates impenetrable cryptographic protection, highly intelligent administrative support features, and strictly governed database access mechanisms to provide a globally secure, exceptionally scalable, and highly efficient digital healthcare record management solution.

METHODOLOGY

6.1 Proposed Methodology Overview
The methodology designed for the Cryptography-EHR platform represents a comprehensive, highly secure pipeline aimed at managing and protecting sensitive Electronic Health Records (EHR). The system moves beyond traditional database perimeter defenses by integrating state-of-the-art multi-layered cryptography, strict Role-Based Access Control (RBAC), and autonomous auditing mechanisms.
The core flow of the methodology consists of five interconnected phases:
1. Data Acquisition and Normalization: Sourcing and standardizing patient diagnostics, symptom queries, and user identities.
2. Cryptographic Preprocessing: Hashing sensitive identities and normalizing inputs for secure database consumption.
3. Dual-Layer Cryptographic Architecture (AES-256 & RSA): Fusion of symmetric bulk encryption with asymmetric digital signatures to guarantee confidentiality and clinical non-repudiation.
4. Intelligent Symptom-to-Specialization Routing: Dynamically mapping unstructured patient complaints to active hospital resources.
5. Autonomous Auditing and Dual-Channel Alerting: Transforming standard database logs into an active, human-auditable security network utilizing Twilio API for immediate clinical alerts.
In addition to these stages, the system ensures seamless, encrypted communication between the backend Node.js engines and the React-based clinician interface, enabling authorized professionals to visualize complex medical data effortlessly. This integrated methodology drastically enhances transparency, reliability, and the legal compliance of health informatics, ultimately supporting healthcare administrators in making secure and informed clinical decisions.

6.2 Data Acquisition and Curation
A highly secure authentication model requires structured and rigorously verified data. The methodology incorporates two primary dataset streams managed exclusively via the MongoDB Atlas cloud:

6.2.1 User Identity and Role Dataset
The identity model categorizes clinical and patient actors with strict hierarchical attributes:
1. Patients: Standard users providing symptom queries, mapping coordinates, and holding read-only access to their personal medical records.
2. Doctors: Authorized medical professionals equipped with unique RSA public/private key pairs natively assigned during registration to digitally sign new records.
3. Pharmacists: Specialized actors permitted to decrypt only specific verified diagnostic prescriptions securely routed to them.
4. Hospital Administrators: Supervisory accounts capable of reviewing immutable security overrides and managing hospital ecosystem metadata.

6.2.2 Clinical and Diagnostic Dataset
The medical knowledge bank requires dynamic processing of highly sensitive text and multimedia payloads:
1. Plaintext Diagnoses: Initial raw medical observations, prescriptions, and test notes generated securely on the doctor's local dashboard.
2. Ciphertext Assets: The permanent stored state of the medical data, entirely encrypted using symmetric block ciphers, retaining strictly zero readability outside of authorized active sessions.

6.3 Data Preprocessing and Normalization
To ensure that the cryptographic algorithms process payloads effectively and maintain absolute database integrity against injection attacks, the raw medical inputs undergo a structured preprocessing pipeline before reaching the MongoDB storage layer. Proper preprocessing dramatically reduces computational overhead during encryption, sanitizes adversarial inputs, and enhances total system reliability.

6.3.1 Payload Standardization and Sanitization
Healthcare datasets often contain vastly different string lengths and character encodings. To maintain consistency, all incoming clinical payloads are aggressively sanitized against script injections and uniformly encoded into UTF-8 standardized buffers. Standardizing textual inputs ensures compatibility with the exact byte-length requirements of the Node.js Crypto streams and stabilizes the computational generation of SHA-256 hashes.

6.3.2 Z-Score Standardization for Security Thresholds
Instead of merely tracking login counts, the system normalizes behavioral access patterns using Z-Score statistical standardization. This technique mathematically computes how far a user's API request frequency deviates from the dataset mean within a specialized time window.

6.3.3 One-Hot Categorical Encoding for Symptom Mapping

6.4 Dual-Layer Cryptographic Architecture
Traditional health platforms commonly deploy holistic database encryption, leaving data entirely exposed if the master system is compromised. Cryptography-EHR fundamentally resolves this by employing a dual-layer cryptographic architecture localized at the document level, seamlessly merging symmetric and asymmetric paradigms via a custom Node.js Crypto backbone.

6.4.1 Symmetric Payload Extraction (AES-256-GCM)
When a doctor submits a diagnostic file, the methodology utilizes Galois/Counter Mode (GCM) paired with an Advanced Encryption Standard (AES) 256-bit key. The AES algorithm dynamically processes the 2D document buffers into a completely randomized ciphertext string. Crucially, GCM inherently generates a highly secure "Authentication Tag," directly providing built-in validation against active ciphertext tampering during database storage.

6.4.2 Asymmetric Integrity Framework (RSA 2048)
Because symmetric keys require complex synchronization, the system incorporates an RSA modular exponentiation framework for pure identity validation. The underlying AES symmetric keys are securely wrapped inside databases specifically mapped via the doctor's specialized public RSA key network.

6.4.3 Feature Hashing and Classification Verification
Before database insertion, a pristine mathematical condensation (SHA-256 Hash) of the plaintext is executed. The system extracts this 256-bit sequence and digitally "signs" it using the doctor's RSA Private Key. This explicit signing process solidifies absolute "Non-Repudiation"—proving unconditionally that a specific, designated physician personally finalized the medical report.

6.5 Autonomous Auditing Implementation (Security Explainability)
A major hurdle in adopting complex cryptographic ecosystems in modern healthcare is maintaining technical oversight without breaking privacy laws. Hospital administrators require explicit forensic evidence of system interactions before classifying events as breaches. The Cryptography-EHR system addresses this by translating deep algorithmic security events into highly intuitive, human-readable visual warning metrics.

6.5.1 Automated Audit Logging

**MODULE 6: MEDICAL CRYPTOGRAPHY ENGINE `(utils/crypto.js)`**
*Handles the highly secure AES-256-GCM encryption of sensitive medical records dynamically.*

```javascript
const crypto = require("crypto");
const ALGORITHM = 'aes-256-gcm';

// Encrypt a single data field
function encryptField(text, aesKey) {
  if (!text) return null;
  const iv = crypto.randomBytes(12);
  const cipher = crypto.createCipheriv(ALGORITHM, aesKey, iv);
  
  let encrypted = cipher.update(text, 'utf8', 'hex');
  encrypted += cipher.final('hex');
  const authTag = cipher.getAuthTag().toString('hex');
  
  // Package payload safely
  return `${iv.toString('hex')}:${authTag}:${encrypted}`;
}

// Decrypt a single data field safely
function decryptField(encryptedStr, aesKey) {
  if (!encryptedStr) return null;
  try {
    const parts = encryptedStr.split(':');
    if (parts.length !== 3) return "[Invalid Format]";

    const iv = Buffer.from(parts[0], 'hex');
    const authTag = Buffer.from(parts[1], 'hex');
    const encryptedText = parts[2];

    const decipher = crypto.createDecipheriv(ALGORITHM, aesKey, iv);
    decipher.setAuthTag(authTag);
    
    let decrypted = decipher.update(encryptedText, 'hex', 'utf8');
    decrypted += decipher.final('utf8');
    
    return decrypted;
  } catch (err) {
    console.error("Field Decryption Error:", err.message);
    return "[Decryption Failed]";
  }
}
```

```javascript
const crypto = require("crypto");

// Sign a diagnostic hash utilizing the Doctor's RSA Private Key
function signData(dataBuffer, privateKeyPem) {
  const sign = crypto.createSign('SHA256');
  sign.update(dataBuffer);
  sign.end();
  return sign.sign(privateKeyPem, 'base64');
}

// Verify a record's authenticity actively during decryption
function verifyData(dataBuffer, signatureBase64, publicKeyPem) {
  const verify = crypto.createVerify('SHA256');
  verify.update(dataBuffer);
  verify.end();
  return verify.verify(publicKeyPem, signatureBase64, 'base64');
}
```

**MODULE 10: ROLE-BASED ACCESS CONTROL MIDDLEWARE `(middleware/rbac.js)`**
*Filters routes dynamically, protecting sensitive endpoints from unauthorized requests.*

```javascript
const jwt = require("jsonwebtoken");

function authorizeRoles(...allowedRoles) {
  return (req, res, next) => {
    const authHeader = req.headers['authorization'];
    if (!authHeader) return res.status(403).send("Authorization header missing.");

    const token = authHeader.split(" ")[1];
    try {
      const decodedUser = jwt.verify(token, process.env.JWT_SECRET);
      
      // Determine if the validated user's role exists within the allowed array
      if (!allowedRoles.includes(decodedUser.role)) {
        return res.status(401).send(`Access Denied: Role '${decodedUser.role}' is inadequate.`);
      }
      
      req.user = decodedUser;
      next();
    } catch (err) {
      return res.status(401).send("Invalid or expired session token.");
    }
  };
}

module.exports = authorizeRoles;
```

### Abstract
**Electronic Health Records (EHRs) have reshaped healthcare delivery by replacing paper-based documentation with centralized digital systems that enable rapid access to patient information. Despite these benefits, concerns surrounding privacy, data breaches, and computational overhead remain significant barriers to widespread adoption—especially in mobile and resource-constrained environments. Traditional hybrid cryptographic frameworks, particularly those combining AES and RSA, enhance confidentiality but often introduce substantial processing latency. In some reported implementations, encrypting a 500 KB medical record requires over five seconds, making real-time clinical usage inefficient.**

**This study presents an optimized Bio-ECC-AES hybrid framework designed to improve both performance and emergency accessibility without compromising security. The proposed model replaces RSA-2048 with Elliptic Curve Cryptography (ECC-256) for key exchange, achieving equivalent cryptographic strength with dramatically reduced computational cost. Experimental evaluation demonstrates a reduction in key generation time from 1240.28 ms to 5.16 ms. Additionally, AES-GCM is employed instead of separate AES-CBC and SHA-256 modules, enabling authenticated encryption in a single operation and improving encryption efficiency by 16.26%.**

**Beyond performance enhancements, the framework introduces an emergency “Break-Glass” mechanism based on Fuzzy Vault bio-cryptography. This allows secure recovery of decryption keys using patient biometrics during critical situations where explicit consent cannot be obtained. Implemented using a Node.js and MongoDB architecture, the system supports encrypted storage of diverse medical formats, including PDF and JPG files. The results indicate that the proposed framework offers a high-performance, scalable, and patient-centric alternative to legacy hybrid EHR security models.**

## I. INTRODUCTION
The digital transformation of healthcare has led to the widespread adoption of Electronic Health Records (EHRs), replacing traditional paper-based medical documentation. By consolidating laboratory results, imaging reports, prescriptions, and clinical notes into unified digital systems, EHRs enhance efficiency, reduce administrative errors, and improve continuity of care. However, the same centralization that makes EHR systems convenient also makes them attractive targets for cyberattacks.

Healthcare data is particularly sensitive. Unauthorized disclosure can lead not only to privacy violations but also to discrimination, reputational damage, and financial harm for patients. As a result, ensuring confidentiality, integrity, and controlled access has become a foundational requirement of modern EHR architectures.

Hybrid cryptographic models have emerged as a practical solution to these challenges. A widely adopted approach combines the Advanced Encryption Standard (AES) for data encryption with the Rivest–Shamir–Adleman (RSA) algorithm for secure key exchange. While this AES-RSA model strengthens security compared to standalone encryption methods, it introduces measurable computational overhead. Prior evaluations report encryption processing times exceeding five seconds for moderately sized medical records (500 KB), along with increased memory consumption. Such delays are problematic in mobile healthcare applications and emergency clinical workflows, where timely access to information is critical.

Another limitation of conventional EHR security frameworks is their reliance on rigid role-based access control. Although effective for routine operations, static access policies can obstruct urgent treatment when patients are unconscious or otherwise unable to provide authorization. In emergency medicine, delays caused by encryption barriers may compromise patient outcomes.

To address these concerns, this research proposes an optimized Bio-ECC-AES hybrid framework. The model replaces RSA-2048 with Elliptic Curve Cryptography (ECC-256), significantly reducing key management latency while maintaining equivalent security strength. Furthermore, AES-GCM is adopted to provide integrated confidentiality and integrity verification within a single cryptographic process. In addition, a biometric “Break-Glass” mechanism based on the Fuzzy Vault scheme is incorporated to enable secure emergency access through patient biometrics.

By combining performance optimization with emergency-ready functionality, the proposed framework aims to deliver a secure, scalable, and practical solution for next-generation EHR systems.

## II. RELATED WORK
The protection of medical information has long been a central concern in healthcare informatics. As hospitals transitioned from paper-based documentation to electronic record systems, researchers began exploring cryptographic mechanisms capable of safeguarding highly sensitive patient data. Over time, various approaches have been proposed to balance confidentiality, integrity, accessibility, and computational efficiency. This section reviews key developments relevant to the proposed Bio-ECC-AES framework.

### A. Hybrid AES-RSA Cryptographic Models
One of the most widely studied approaches for securing Electronic Health Records involves combining symmetric and asymmetric cryptography. In such hybrid systems, the Advanced Encryption Standard (AES) is used to encrypt patient data due to its speed and efficiency, while the Rivest-Shamir-Adleman (RSA) algorithm is employed for secure key exchange. This AES-RSA combination improves confidentiality compared to single-algorithm solutions and has been shown to provide strong protection against unauthorized access.

However, performance analyses of these systems reveal certain limitations. While encryption strength is enhanced, RSA-based key management introduces noticeable latency. Empirical evaluations indicate that processing moderately sized medical files (approximately 500 KB) can require several seconds, particularly during key generation and encryption phases. This computational cost becomes more pronounced in mobile or resource-constrained environments, where processing power and battery capacity are limited. As a result, the AES-RSA model, although secure, does not fully resolve the security-performance trade-off.

### B. Bio-Cryptography and Biometric Key Protection
Beyond traditional encryption models, researchers have explored integrating biometric characteristics into cryptographic systems. Bio-cryptography leverages unique human traits—such as fingerprints or iris patterns—to secure or reconstruct encryption keys. Techniques such as the fuzzy vault and fuzzy commitment schemes bind cryptographic secrets to biometric feature sets, making key recovery dependent on legitimate biological input.

Studies in this domain demonstrate promising resistance against impersonation attacks, often reporting negligible false acceptance rates when implemented under controlled conditions. These approaches are particularly attractive for healthcare systems because they align with patient-centric authentication models. However, many implementations focus primarily on authentication rather than integrating biometric mechanisms into broader hybrid encryption frameworks.

### C. Attribute-Based Encryption for Medical Records
Another line of research addresses flexible access control through Attribute-Based Encryption (ABE). In ABE systems, decryption rights are associated with user attributes rather than predefined roles. This allows more dynamic access policies and supports fine-grained permission structures within medical institutions. ABE has been applied to mobile healthcare environments, enabling patients to manage their own encrypted records while granting selective access to healthcare providers.

Despite its flexibility, ABE often introduces additional computational complexity, especially during key generation and policy enforcement. Furthermore, most evaluations emphasize encryption and decryption timings without comprehensively assessing memory consumption or scalability within real-world hospital infrastructures.

### D. Lightweight and Elliptic Curve Cryptography Approaches
To reduce computational overhead, recent studies have explored lightweight cryptographic alternatives. Elliptic Curve Cryptography (ECC) has gained particular attention due to its ability to provide equivalent security strength with significantly smaller key sizes compared to RSA. By relying on the mathematical difficulty of the Elliptic Curve Discrete Logarithm Problem (ECDLP), ECC achieves strong protection while reducing processing time and storage requirements.

Comparative analyses consistently demonstrate that ECC-based key exchange mechanisms outperform RSA in terms of efficiency. These characteristics make ECC especially suitable for mobile healthcare applications and Internet-of-Medical-Things (IoMT) environments, where computational resources are constrained. Nevertheless, many existing frameworks implement ECC primarily for key exchange without integrating optimized authenticated encryption modes or emergency-access provisions.

### E. Identified Research Gap
Although substantial progress has been made in securing electronic medical records, existing solutions often require a compromise between strong security and operational efficiency. Hybrid AES-RSA systems provide robust encryption but suffer from latency issues. Biometric methods enhance authentication but are rarely incorporated into full-scale hybrid architectures. Attribute-based models improve flexibility yet introduce additional complexity. Meanwhile, many systems lack a practical and secure emergency-access mechanism for situations in which patients cannot provide consent.

The proposed Bio-ECC-AES framework addresses these limitations by combining three key elements: the efficiency of ECC-based key exchange, the integrated authenticated encryption of AES-GCM, and a biometric break-glass mechanism based on the fuzzy vault scheme. By merging performance optimization with emergency accessibility, the framework aims to bridge the gap between theoretical cryptographic strength and real-world clinical practicality.

## III. PROPOSED METHODOLOGY

### A. System Overview
The proposed framework introduces a secure and performance-optimized architecture for protecting Electronic Health Records (EHRs). The design integrates efficient asymmetric key exchange, authenticated symmetric encryption, and biometric-based emergency recovery into a unified model. The objective is to ensure confidentiality, integrity, availability, and controlled emergency access without imposing excessive computational overhead.

The architecture consists of five primary layers:
- **User Interface Layer:** Used by patients, doctors, and administrators for authentication and record access.
- **Authentication Layer:** Handles identity verification using credentials and biometric validation.
- **Cryptographic Processing Layer:** Performs key exchange, encryption, decryption, and integrity verification.
- **Secure Storage Layer:** Stores encrypted EHR data in the cloud or hospital server.
- **Emergency Break-Glass Module:** Enables controlled access during critical medical situations.

Each component is designed to operate independently yet cohesively within the system’s overall security workflow.

### B. Cryptographic Framework Design
**1) Key Exchange using Elliptic Curve Cryptography (ECC):** To minimize computational overhead while maintaining strong security, the system employs Elliptic Curve Cryptography for secure session key establishment. ECC provides equivalent security to RSA with significantly smaller key sizes, reducing both processing time and memory usage.

The security of ECC is based on the Elliptic Curve Discrete Logarithm Problem (ECDLP), which is computationally infeasible to solve using classical computing techniques.
The elliptic curve equation used is:
*y^2 = x^3 + ax + b (mod p)* (1)
Where:
- *a* and *b* are curve parameters,
- *p* is a large prime number,
- The curve satisfies the condition: *4a^3 + 27b^2 ≠ 0 (mod p)*

A shared secret session key is generated through Elliptic Curve Diffie-Hellman (ECDH), ensuring that encryption keys are never transmitted directly.

**2) Data Encryption using AES-GCM:** After secure key establishment, patient records are encrypted using Advanced Encryption Standard (AES) in Galois/Counter Mode (GCM).
AES-GCM is selected because it provides:
- Confidentiality (via symmetric encryption)
- Integrity (via authentication tag)
- Protection against replay attacks
- Reduced computational passes (encryption + authentication in one step)

The AES encryption process can be expressed as:
*C = AES_K(P)* (2)
Where:
- *P* is the plaintext medical record,
- *K* is the session key derived from ECC,
- *C* is the ciphertext.

The GCM authentication tag ensures that any tampering with encrypted medical data is immediately detected during decryption.

**3) Secure Storage Model:** Encrypted records are stored in a cloud or hospital database in ciphertext form. The system never stores plaintext data on persistent storage. Each stored record includes:
- Encrypted medical file
- Associated authentication tag
- Metadata (timestamp, record ID)
- Encrypted session key (protected via ECC)

This ensures that even if the storage server is compromised, attackers cannot retrieve meaningful information without the corresponding private key.

### C. Biometric Break-Glass Mechanism
**1) Rationale for Emergency Access:** In medical emergencies, patients may be unconscious or unable to provide consent. Traditional encryption models prevent access under such conditions, potentially delaying life-saving treatment. To address this limitation, the framework incorporates a controlled break-glass mechanism secured through biometric cryptography.

**2) Fuzzy Vault-Based Key Recovery:** The system employs a fuzzy vault scheme to bind a cryptographic secret with a patient’s biometric template (e.g., fingerprint).
The process consists of:
- Extracting biometric feature points.
- Encoding the encryption key as a polynomial.
- Locking the polynomial using genuine biometric features mixed with random chaff points.

Vault locking process:
*V = {(x_i, P(x_i))} U "Chaff Points"* (3)
Where:
- *P(x)* represents a polynomial encoding the secret key.
- Genuine feature points unlock the vault.
- Chaff points obscure the structure to prevent brute-force reconstruction.

During emergency access:
- A doctor submits biometric input.
- If sufficient genuine feature overlap exists, the vault reconstructs the polynomial.
- The recovered key decrypts the EHR.
All emergency accesses are logged and audited to prevent misuse.

### D. Authentication and Access Control
The system implements multi-factor authentication consisting of:
- Username and password verification
- Biometric authentication
- Role-based access control (RBAC)

Access privileges are categorized as:
- Patient-level access
- Physician-level access
- Administrative-level access
- Emergency override access

This layered approach ensures that users can only access records within their authorization scope.

### E. System Workflow
The operational workflow follows five stages:
**Stage 1: Registration**
- User registers with credentials and biometric template.
- ECC key pair is generated.
- Biometric data is transformed into vault representation.

**Stage 2: Record Upload**
- EHR is encrypted using AES-GCM.
- Session key secured via ECC.
- Ciphertext stored in secure database.

**Stage 3: Normal Access**
- User authentication verified.
- ECC session key reconstructed.
- AES decryption performed.
- Integrity validated through authentication tag.

**Stage 4: Emergency Access**
- Doctor initiates break-glass request.
- Biometric vault unlocked.
- Key reconstructed.
- Access granted and logged.

**Stage 5: Audit and Monitoring**
- All operations logged.
- Suspicious activity triggers alerts.
