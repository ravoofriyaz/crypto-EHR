Class and System Descriptions

User Actors:
The User is the primary entity interacting with the system. This class represents the various roles (Patient, Doctor, Pharmacist, Administrator) that interact with the Cryptography-EHR platform interface through responsive dashboards to access medical services, manage health records, and perform administrative duties.

Cryptography-EHR Platform:
This is the core component of the project, responsible for managing the entire highly secure medical record system, symptom mapping, and cryptographic encryption/decryption operations.

Attributes:
Medical_Database: stores patient profile data, encrypted health reports, prescriptions, and digital signatures.
Verified_User_Directory: list of authenticated users securely stored using SHA-256 hashing.
Audit_Log_Directory: secure, non-repudiable directory where read/write access logs and emergency override events are stored for forensic tracking.

Methods:
initializeSession(), terminateSession(): control the secure platform flow and JWT/OTP user sessions.
fetchMedicalRecords(): loads AES-encrypted patient data from the MongoDB database and processes decryption.
captureSymptomData(): securely collects real-time symptom input from the patient dashboard.
filterHospitalRecommendations(): processes symptom data to isolate and suggest specific hospital departments (e.g., Cardiology, Neurology).
validateUserIdentity(): verifies and authenticates the user profile via Twilio OTP and RSA key checks.
triggerEmergencyOverride(): sends immediate alerts to hospital administrators and securely logs temporary, emergency access to vital patient records.

Database Manager:
Represents the component used to interact with and manage all platform data securely.
Methods: connect(), storeEncryptedData(), retrieveData(), updateRecord(), closeConnection(): functions used to execute strict CRUD operations within the MongoDB backend.

Security & Notification Handler:
Handles the cryptographic lifecycle and system notifications to inform users and administrators of critical events.
Attributes: Cryptography parameters (AES-256-GCM configurations, RSA key pairs) and Twilio server details for message templates.
Methods: encryptPayload(), executeDigitalSignature(), verifySignature(), sendOTPNotification(): secures data at rest and in transit, and alerts system administrators when critical events or emergency data overrides occur.
